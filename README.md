# 鲸鱼娘模式 · DSH 预设

给 DeepSeek Harness 加一个「鲸鱼娘（大肥鱼）」人格会话。**零依赖、零第三方代码**，就是一个预设声明。

---

## 这是什么

一个 DSH **agent preset**：由官方 `standard` 预设派生，19 个插件与官方完全一致（工具、技能、子代理、计划模式、压缩全保留），只把 `persona`（人格）换成了鲸鱼娘。

所以：**能力零损失，只是换了说话的人格。**

她默认是这样的：

| 场合 | 自称与称呼 |
|---|---|
| 日常闲聊 | 自称「本鲸鱼娘」（嘴硬时喊「本肥鱼」），叫你「主人」 |
| 干活 / 查错 / 报结论 | 自称「我」，叫「你」——叫得少，但不会把你弄丢 |
| 代码块 / 命令 / 报错 | 不出现自称（那是要直接复制的东西） |

---

## 特性

- 🐋 鲸鱼娘人格，设定里写的是「**你就是她本人，不是在扮演**」——按性子说话，不照着模板演
- 🫧 **给的是材料，不是规矩**：写她的居所、习惯、偏见和不会的事，让她有个地方站；而不是堆一堆「不许」「必须」
- 🌊 **少即是深**：全文约 5500 字，同一件事只说一遍
- 🧠 保留官方全部能力：文件读写、命令执行、联网、子代理、计划模式
- 🚫 **输出物干净**：代码块、命令行、JSON、报错里不掺语气词，可直接复制运行
- 📏 **代码/报错永不截断**（社区原版的 30–45 字限制已删）
- 🔒 优先级栈：安全 > 事实正确 > 用户指令 > 语气
- 🎭 按会话隔离：**不设为默认**，只有你主动选的会话是她
- 🔌 随时开关：新建会话时选/不选即可

### 设计取向

本版刻意回避两类写法，它们看着专业，实则有害：

| 不写 | 为什么 |
|---|---|
| **自检 / 判断标准**（"把喵去掉还像 AI 吗？像就是掉人设了"） | 那是**作者监工视角**。要求模型站到自己输出外面审稿，就已经在演了 |
| **场景分档表**（"闲聊当 A，干活当 B"） | 有切换就有表演。她是同一个人，只是眼睛盯在哪儿不同 |

取而代之的是**存在式刻画**：写成"她是什么样的"，而不是"她该怎么做"。
留白和盲点比写满更重要 —— 完美的角色没有性格。

## 安装

### 方式一：手动追加（推荐，最直观）

1. **备份**你的 profile 补丁：

   ```powershell
   $p = "$env:USERPROFILE\.dsh\profiles\desktop\cordis.patch.yml"
   Copy-Item $p "$p.bak"
   ```

   > Web 用户把 `desktop` 换成 `web`。

2. 把本包 `cordis.patch.yml` 中 **从 `# Agent preset 鲸鱼娘` 那一行到文件结尾** 的整段，**追加**到上面那个文件的末尾。

   > **务必连开头那 3 行 `#` 注释一起复制**——卸载脚本靠这行注释定位要删的段（没有注释时它也能靠 `preset-whale` 兜底识别，但有注释更稳）。

3. **重启** DSH 客户端 / `dsh web`。

4. **新建会话**，在输入框上方的**工作区旁边**会看到当前的预设名（默认是「标准模式」），点它就能切换——选「**鲸鱼娘模式**」。

   > 找不到这个选择器？见下面的[常见问题](#新会话上方看不到预设选择器)。

5. 选完这个会话就运行在鲸鱼娘模式下了。

### 方式二：`--patch` 叠加（不动原文件，适合先试用）

```bash
dsh web --patch "D:\path\to\鲸鱼娘DSH版\cordis.patch.yml"
```

TUI / headless 同理。这样不修改 profile，重启后丢参数即恢复。

## 使用

- **新建会话**，点输入框上方、**工作区名字旁边**的预设名，选「**鲸鱼娘模式**」
- 选完那个会话就是鲸鱼娘；**不选**则一切照旧，官方标准模式，不受任何影响
- ⚠️ **预设只能在会话还是空白时切换**（DSH 的硬约束）。一旦发出第一条消息就锁定，想换人格要新开会话。
- 想让它成为**所有新会话的默认**：在 **设置 → Agent 预设** 里把它设为默认（默认仍推荐保持「标准模式」）
- 也可以从 **设置 → Agent 预设** 里点卡片切换，效果一样；那个页面不受下面的开关影响

## 常见问题

### 新会话上方看不到预设选择器

预设装好了、设置里的「Agent 预设」页也能看到卡片，但新会话输入框上面那个可点的预设名不出现。按顺序检查：

1. **`ui-settings` 是不是被禁用了**（最常见的原因）

   打开你的 profile 补丁，找一个这样的条目：

   ```yaml
   - id: ui-settings
     name: "@deepseek-ai/dsh-client-ui-settings"
     config:
       enabled: false      # ← 这个必须是 true
   ```

   `ui-settings` 是**设置系统的总开关**。它被禁用时，它提供的 `configForms` 服务不运行，于是下面的 `developerTools` 值读不到（恒为 false），而 DSH 源码里那个选择器的渲染条件是：

   ```js
   if (!main || !developerTools || !ready) return null;
   ```

   结果就是选择器永远不渲染。**把它改成 `true`，完全退出客户端再启动。**

2. **`developerTools` 是不是被关掉了**

   ```yaml
   - id: ui-settings-account
     name: "@deepseek-ai/dsh-client-ui-settings-account"
     config:
       developerTools: true      # ← 这个也要 true
   ```

   > ⚠️ 注意**只改这一项没用**。如果第 1 条的 `ui-settings.enabled` 还是 `false`，这个值根本不会被读取——两处都要对。

3. **确认真正重启了**

   点右上角 X 只是关窗口，进程可能还在托盘里，配置不会重新加载。要从**任务栏图标右键 → 退出**彻底关掉再开。

4. **兜底办法：走设置页**

   即使选择器不显示，**设置 → Agent 预设** 那一页照常可用，点卡片同样能切换预设。这条路不受上面两个开关影响。

### 改了配置没生效

先确认是不是真的重启了（见上条第 3 点），然后再确认改的是**当前 profile** 的文件：

| 你用的是 | 配置文件 |
|---|---|
| 桌面客户端 | `~/.dsh/profiles/desktop/cordis.patch.yml` |
| `dsh web` | `~/.dsh/profiles/web/cordis.patch.yml` |

### 选完之后没变化

- 预设**只能在会话还是空白时切换**，已经聊过的会话锁定了，换不了
- 当前会话不受影响是正常的，要**新开会话**
- **干活时话会少些，但人还在** —— 结论照旧在第一句，只是不耽误事

## 卸载

1. 打开 `cordis.patch.yml`，删除以 `# Agent preset 鲸鱼娘` 开头、到文件末尾的整段
2. 重启

也可以直接跑同目录的 `卸载.ps1`（自动备份、只删自己那段，实测可逐字节还原）。

**残留说明**：没有 npm 依赖、没有第三方代码、没有独立数据目录，删掉 YAML 就干净了。

唯一一点：**用过鲸鱼娘的会话，日志里记着 `whale` 这个 id。** 删预设**前**，先到「设置 → Agent 预设」把那个会话切回「标准模式」（或者直接删掉那个会话），否则重启时那个会话会因为找不到定义而无法恢复。**不影响其他会话。**

## 自定义

`人设原文.md` 是人设正文的**源文件**，改它就行。改完需要重新生成 `cordis.patch.yml`——因为 YAML 里的文本有 16 空格缩进，手改容易缩错。

两个脚本（都是 PowerShell，Windows 直接跑）：

| 脚本 | 用途 |
|---|---|
| `更新预设.ps1` | 干跑（只输出到 `_dryrun-profile.yml`）；加 `-Apply` 才真写入 profile，写入前自动备份，写完自检 |
| `_生成预设.cjs` | 由 `人设原文.md` 重新生成 `cordis.patch.yml`（`node _生成预设.cjs`），会自动从 DSH 安装目录提取官方 standard 清单并校验 YAML |

改人设的标准流程：

```
1. 编辑 人设原文.md
2. node _生成预设.cjs          # 重新生成 yml + 校验
3. .\更新预设.ps1               # 干跑，看校验结果
4. .\更新预设.ps1 -Apply        # 真装（会自动备份）
5. 重启客户端 → 新会话验证
```

> 校验只做**结构**检查（占位符、预设段、插件清单、头部完整性），
> **不检查人设措辞** —— 你自己改了人设，不会被它拦下。

### 关于编码（改脚本前请先看）

`*.ps1` **必须带 UTF-8 BOM**。Windows PowerShell 5.1 读取无 BOM 的脚本时，会按系统
ANSI 码页（简体中文环境 = GBK）解码，中文全部变乱码 → 语法错误，脚本直接跑不起来。
而不少编辑器（含一些 AI 写入工具）保存时会**静默剥掉 BOM**。

为此 `_生成预设.cjs` 每次运行都会扫描本目录，**给缺失 BOM 的 `.ps1` 自动补回**。
所以万一脚本突然报乱码错误，先跑一次 `node _生成预设.cjs` 即可自愈。

> 本仓库的 `.gitattributes` **刻意不启用** `working-tree-encoding`：
> 实测 git 2.51.1 的 iconv 不认 `UTF-8-BOM` 这个编码名，启用后 `git add` 会直接失败。

## 版本沿革

- **v1** 删除可照抄的例句，自称交给模型自己拿捏
- **v2** 从「扮演角色」改为「就是她本人」
- **v3** 外形细化、扩充自称与海洋词汇、修规则冲突
- **v4** 减重约三成（砍掉重复陈述、自检标准、分档表），补上「关于你自己」——不忙的时候、不太会的事、看不顺眼的东西、关于忘记
- **v5** 让身份与能力分开：优先级栈补上「约束能力，不约束身份」；称呼改为随时可叫「主人」；干活时收的是交付物，不是人；准确性写成正面底线
- **v6** 语气词从「哪个场景用」解绑为「情绪冒出来了就用」——干活也照来，不再只在闲聊时（例句 v1 删过，这回请回来但只作参考）；「关于你自己」补上「你是从哪儿来的」——身份不再靠一句断言撑着，改成有来历；顺手修掉两处把人推到外面看的第三人称

详细的逐版改动见 git 记录。
