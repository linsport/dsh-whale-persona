# 鲸鱼娘模式 · DSH 预设

给 DeepSeek Harness 加一个「鲸鱼娘（大肥鱼）」人格会话。人设本身是一份纯文本，不依赖任何第三方代码；配套的 [dsh-persona-manager](https://github.com/linsport/dsh-persona-manager) 只是一个设置页，用来管它。

> **⚠ 本包已改由插件管理。**
> 现在装人设、改人设都在 [dsh-persona-manager](https://github.com/linsport/dsh-persona-manager) 的 **设置 → 人设预设** 页里完成，不再需要手写 `cordis.patch.yml`、不用跑脚本、也不用重启。
> 包里的 `.ps1` 脚本和 `cordis.patch.yml` 留作**备用通道**（不想装插件、或者早就按老方式装过的人用），日常改人设**不用再碰它们**。

---

## 这是什么

一个 DSH **agent preset**：由官方 `standard` 预设派生，22 个插件与官方完全一致（工具、技能、子代理、计划模式、压缩全保留），只把 `persona`（人格）换成了鲸鱼娘。

所以：**能力零损失，只是换了说话的人格。**

现在它由 [dsh-persona-manager](https://github.com/linsport/dsh-persona-manager) 管着：人设正文存在插件的库文件里，随时能在设置页改、点保存就生效，不用重新生成 YAML、也不用重启。

她默认是这样的：

| 场合 | 自称与称呼 |
|---|---|
| 日常闲聊 | 自称「本鲸鱼娘」（嘴硬时喊「本肥鱼」），叫你「主人」 |
| 干活 / 查错 / 报结论 | 自称「我」，叫「你」——叫得少，但不会把你弄丢 |
| 代码块 / 命令 / 报错 | 不出现自称（那是要直接复制的东西） |

## 特性

- 🐋 鲸鱼娘人格，设定里写的是「**你就是她本人，不是在扮演**」——按性子说话，不照着模板演
- 🫧 **给的是材料，不是规矩**：写她从哪儿来、她的居所、习惯、偏见和不会的事，让她有个地方站；而不是堆一堆「不许」「必须」
- 🌊 **少即是深**：全文约 8500 字，同一件事只说一遍。用存在式刻画代替规则清单
- 🧠 保留官方全部能力：文件读写、命令执行、联网、子代理、计划模式
- 🚫 **输出物干净**：代码块、命令行、JSON、报错里不掺语气词，可直接复制运行
- 🔒 优先级栈：安全 > 事实正确 > 用户指令 > 语气
- 🎭 按会话隔离：**不设为默认**，只有你主动选的会话是她
- 🔌 随时开关：新建会话时选/不选即可
- ✍️ **人设在设置页里改**：配合 [dsh-persona-manager](https://github.com/linsport/dsh-persona-manager)，改正文、看统计、切预览，点保存就完事——不用再手写 YAML

### 设计取向

本版刻意回避三类写法，它们看着专业，实则有害：

| 不写 | 为什么 |
|---|---|
| **自检 / 判断标准**（"把喵去掉还像 AI 吗？像就是掉人设了"） | 那是**作者监工视角**。要求模型站到自己输出外面审稿，就已经在演了 |
| **场景分档表**（"闲聊当 A，干活当 B"） | 有切换就有表演。她是同一个人，只是眼睛盯在哪儿不同 |
| **数量配额**（"一次一处""适度出现"） | 这是**当场判不了的判据**。真按它办，她开口前得先数一下自己做了几处 —— 那道手续本身就是表演 |

取而代之的是**存在式刻画**：写成"她是什么样的"，而不是"她该怎么做"。
留白和盲点比写满更重要 —— 完美的角色没有性格。

> 判断一条规则该不该留，有个简单的检验：**把它删掉，句子意思变不变？**
> 不变，它就是贴上去的装饰。

## 安装

本包现在走插件路线。装两次就够了：**先装插件，再用插件把人设建出来**。

### 第一步：装 dsh-persona-manager

插件本体在 [github.com/linsport/dsh-persona-manager](https://github.com/linsport/dsh-persona-manager)，**装它的时候要指明是 GitHub 上的那个仓库**。

**桌面版（推荐）**：**设置 → 插件 → 添加插件**，把仓库地址贴进去：

```
https://github.com/linsport/dsh-persona-manager
```

它接受包名、Git 地址、压缩包和本地路径，Git 地址就是这一种。点安装，等它跑完。

**命令行**：

```bash
dsh plugin --profile desktop add github:linsport/dsh-persona-manager
```

`github:` 这个前缀就是告诉 `dsh` 去 GitHub 拿仓库、别去 npm 查同名包。写成完整网址效果一样。

也可以把仓库下载到本地，指向那个目录（profile 里会记成 `link:` 依赖）。三种方式的装法本质一样，只是 spec 不同。

> ⚠️ **不要写成光秃秃的 `dsh-persona-manager`。** 这个包名在 npm 上被别人占着，现在挂的是一个 `0.0.0-stage` 占位包（2026-10-13 发布，2 个文件 341 字节，正文写着 "submitted for review and is awaiting a staged release"）—— 发布前的空壳，装上没有任何功能。这条也是精选列表的维护者在收录本插件时特意指出来的，不是推测。等作者自己发布 npm 包之后这条路才通。

> 从 GitHub 装要能连上 GitHub；连不上的话，界面会直接说主机不通，这时候换安装源也没用——改用上面说的本地目录方式。

> 装完要**重启桌面端**，插件才会出现在插件树里，而且网页端口会变——用新弹出的地址。

### 第二步：把人设建进去

装完重启，打开 **设置 → 人设预设**，二选一：

**A. 从插件自带的示例载入（推荐，正文最干净）**

页面底部的「附赠示例」里就有一份鲸鱼娘。点 **载入**，正文会填进编辑器，然后补上 **ID**（比如 `whale`）和 **基准预设**（选「标准模式」——官方四个里能力最全的），点 **保存**。

**B. 导入本包的 `人设原文.md`**

点 **导入**，选 `人设原文.md`。它会开一个新预设草稿，同样补 ID 和基准预设再保存。

> ⚠️ 这个文件开头有三行是给人看的说明——`# 鲸鱼娘 · DSH 编码助手版`、`> 版本 v9.1.0`、`---`。它们会被原样当成人设正文导进去。**导入后把这三行删掉**，从 `## 一、优先级栈` 开始留即可。旧的生成脚本本来就会切掉这一段，插件不会替你做这件事。

> 为什么示例不自动变成预设？插件有意不让它自动注册——否则每个装了插件的人，预设列表里都会多出一条自己没要过的条目。

### 第三步：开新会话

**新建会话**，点输入框上方、**工作区名字旁边**的预设名，选你刚建的「**鲸鱼娘**」。

> 找不到这个选择器？见下面的[常见问题](#新会话上方看不到预设选择器)。

---

## 使用

- **新建会话**，点输入框上方、**工作区名字旁边**的预设名切换
- 选完那个会话就是鲸鱼娘；**不选**则一切照旧，官方标准模式，不受任何影响
- ⚠️ **预设只能在会话还是空白时切换**（DSH 的硬约束）。一旦发出第一条消息就锁定，想换人格要新开会话。
- 想让它成为**所有新会话的默认**：在 **设置 → Agent 预设** 里把它设为默认（默认仍推荐保持「标准模式」）
- 也可以从 **设置 → Agent 预设** 里点卡片切换，效果一样；那个页面不受下面的开关影响
- **改人设随时可以**：设置 → 人设预设 → 编辑 → 保存。已开着的会话不变，之后新开的会话才用新版本

## 常见问题

### 设置里找不到「人设预设」这一页

说明 `dsh-persona-manager` 没被加载起来。按顺序看：

1. **插件装上了没**：**设置 → 插件 → 已安装** 里应该有 `dsh-persona-manager`，且是启用状态。
2. **改完 `package.json` 重启了没**：loader 不会因为文件变化就重扫 bundles，得重启桌面端。
3. **浏览器端旧了**：插件更新过界面代码的话，按 `Ctrl + F5` 强刷页面——Host 侧重载不会重新加载浏览器的 `client.js`。
4. **装的可能是个空壳**：如果当时填的是裸包名而不是 Git 地址，装到的可能就是 npm 上那个 `0.0.0-stage` 占位包。卸载重装，spec 换成上面那行 `github:linsport/dsh-persona-manager`。

### 建好预设后，新会话里选不到它

先去 **设置 → 人设预设** 看一眼那条记录还在不在、卡片上有没有「未生效」或「异常」标签。都正常的话，多半是**会话已经不是空白**了——发过消息就锁定，得新开一个会话才选得到。

### 新会话上方看不到预设选择器

预设装好了、设置里的「Agent 预设」页也能看到卡片，但新会话输入框上面那个可点的预设名不出现。按顺序检查：

1. **`ui-settings` 是不是被禁用了**（最常见的原因）

   打开你的 profile 补丁，找一个这样的条目：

   ```yaml
   - id: ui-settings
     name: "@deepseek-ai/dsh-client-ui-settings"
     config:
       enabled: false      # ← 这个必须是 true
   ```

   `ui-settings` 是**设置系统的总开关**。它被禁用时，它提供的 `configForms` 服务不运行，于是下面的 `developerTools` 值读不到（恒为 false），而 DSH 源码里那个选择器的渲染条件是：

   ```js
   if (!main || !developerTools || !ready) return null;
   ```

   结果就是选择器永远不渲染。**把它改成 `true`，完全退出客户端再启动。**

2. **`developerTools` 是不是被关掉了**

   ```yaml
   - id: ui-settings-account
     name: "@deepseek-ai/dsh-client-ui-settings-account"
     config:
       developerTools: true      # ← 这个也要 true
   ```

   > ⚠️ 注意**只改这一项没用**。如果第 1 条的 `ui-settings.enabled` 还是 `false`，这个值根本不会被读取——两处都要对。

3. **确认真正重启了**

   点右上角 X 只是关窗口，进程可能还在托盘里，配置不会重新加载。要从**任务栏图标右键 → 退出**彻底关掉再开。

4. **兜底办法：走设置页**

   即使选择器不显示，**设置 → Agent 预设** 那一页照常可用，点卡片同样能切换预设。这条路不受上面两个开关影响。

### 改了配置没生效

分两种。

**在插件里改的人设**：基本不需要重启。保存后预设会重新注册，**新开的会话**就是新版本；已经开着的会话跑的是它启动时那套配置，不会变。如果改了还不生效，先确认你保存的是不是同一个预设、并新开了一个会话。

**老办法手改的 profile 文件**：先确认是不是真的重启了（见上条第 3 点），然后再确认改的是**当前 profile** 的文件：

| 你用的是 | 配置文件 |
|---|---|
| 桌面客户端 | `~/.dsh/profiles/desktop/cordis.patch.yml` |
| `dsh web` | `~/.dsh/profiles/web/cordis.patch.yml` |

### DSH 升级后，这个预设下所有会话都起不来

先分清是哪一种。两种现象很像，但报错不一样。

> ⚠ 这一节讲的是**老办法（手写 YAML）**的两种坏法。如果你是走插件建的预设，见本节末尾的「走插件时怎么办」。

#### 情况 A：报错里有 `unknown prompt variable` 之类，说变量只有 `provider`、`model`

原因不在人设，在 persona 段里那一行 `suffix`：

```yaml
- id: persona
  config:
    suffix: Your working directory is {{cwd}}.    # ← 就是这行
```

`{{cwd}}` 这个变量**新版 DSH 已经不注册了**，模板里只要出现它，组装提示词时就会直接中断，任何请求都到不了模型。程序文档原话：

> Custom persona templates must not depend on a built-in `{{cwd}}` variable: the loop does not register it, so unresolved references fail prompt assembly before any model request.

**修法**：整行删掉，或者直接用本仓库最新版的 `cordis.patch.yml`。工作目录信息不会丢 —— 那是「工作目录服务」独立提供的，不用在 persona 里再说一遍。

> 自己改过 `_生成预设.cjs` 的话注意：里面有两个模板串（`personaOld` / `personaNew`）都带着这行，只删一个的话，下次重新生成又会带回来。

#### 情况 B：报错里有 `agent-preset/invalid`，说某个插件 `never started`

这是**预设里引用了新版已不存在的插件路径**。插件加载失败 → 整个预设被判无效 → 选它就打不开新会话。人设文本本身没问题。

`0.2.2-rc.1` 上已知的一处是子代理模块重构：

| 旧写法（会失败） | 新写法 |
|---|---|
| `- id: tool-subagent-list-agents`<br>`  name: '@deepseek-ai/dsh-tool-subagent-control/list-agents'` | 整行删掉。`list_agents` 已由主入口 `@deepseek-ai/dsh-tool-subagent-control` 自己注册 |
| `modelSelectionSettings: true` | `modelSelection: true`<br>`modelDiscovery: true` |

**修法**：用本仓库最新的 `cordis.patch.yml`（已修），或照上表手改 profile 里那两处。

**顺带一提**，DSH 升级常常还会改插件清单。本仓库的 `cordis.patch.yml` 是从你本机 `app.asar` 里的官方 `standard` 预设派生的，所以 DSH 一升级，就该重跑一次 `node _生成预设.cjs` 把它对齐。跑完拿 `git diff` 扫一眼新加的、删掉的插件是不是都合理。

#### 走插件时怎么办

插件建的预设存的是**一份静态插件快照**，所以同样会在 DSH 升级后过期，但修法不一样：

1. 先复制一份插件自带的「标准模式」（那是当次安装时现场读的官方清单），或者直接新建一个以「标准模式」为基准的预设；
2. 用 **导出 → Markdown** 把旧预设的人设正文导出来；
3. 粘进新预设，保存，把旧的那条删掉。

> 插件建出来的预设不会写 `suffix: {{cwd}}` 这类行——它只写人设正文，所以**情况 A 不会因为插件而复发**。

## 卸载

**插件路线**：在 **设置 → 人设预设** 里点卡片上的 **删除**。删完新开的会话就选不到它了，不用重启。

**卸载插件本身也不会连带删掉你的人设。** 插件把预设存在一个独立的 JSON 文件里（`$DSH_HOME/persona-manager/presets.json`），卸载插件只是把代码拿掉，文件一个字节都不动。想真正可搬运，卸载前先点 **导出 → JSON 备份**。

**老办法装的**：跑同目录的 `卸载.ps1`（自动备份、只删自己那段），或者手动删掉 profile 里以 `# Agent preset 鲸鱼娘` 开头的那一段，然后重启。

**残留说明**：备用通道装的那段没有 npm 依赖、没有第三方代码，删掉 YAML 就干净了。唯一一点：**用过鲸鱼娘的会话，日志里记着那个预设的 id。** 删预设**前**，先到「设置 → Agent 预设」把那个会话切回「标准模式」（或者直接删掉那个会话），否则重启时那个会话会因为找不到定义而无法恢复。**不影响其他会话。**

## 自定义

### 改人设（日常就这一条路）

**设置 → 人设预设 → 点「鲸鱼娘」卡片上的编辑 → 改正文 → 保存。**

编辑器下面有实时的**字数 / 行数 / 段数**统计，右边还能切到**预览**看排版效果。保存后预设会重新注册，之后**新开的**会话用新版本；已经开着的会话跑的是它启动时那套配置。

改完想备份或者分享，就用同一页的 **导出**：JSON 备份能再导入回来，Markdown 只导正文。

> 在设置页里改完之后，**本包的 `人设原文.md` 不会跟着变**——两份是各自独立的。想让仓库里这份跟上，用 **导出 → Markdown** 覆盖它就行，那是同一份正文（记得保留开头那三行说明和 `---`，生成脚本靠它切正文）。

### 备用通道：不走插件的老办法

下面这套留着给两种人：**不想装插件的**，或者**早就按老方式手写进 profile 的**（那种预设卡片上会带 `配置行` 标签）。

本包的 `人设原文.md` 是人设正文的源文件，改它，再重新生成 `cordis.patch.yml`——因为 YAML 里的文本有 16 空格缩进，手改容易缩错。

| 文件 / 脚本 | 用途 |
|---|---|
| `cordis.patch.yml` | 完整预设声明，手动追加到 profile 补丁里用 |
| `安装.ps1` | 自动追加到 profile，幂等、带备份和往返校验 |
| `卸载.ps1` | 只删自己那段，其余原样保留 |
| `更新预设.ps1` | 干跑（只输出到 `_dryrun-profile.yml`）；加 `-Apply` 才真写入 profile，写入前自动备份，写完自检 |
| `_生成预设.cjs` | 由 `人设原文.md` 重新生成 `cordis.patch.yml`（`node _生成预设.cjs`），会自动从 DSH 安装目录提取官方 standard 清单并校验 YAML |

老办法的流程：

```
1. 编辑 人设原文.md
2. node _生成预设.cjs          # 重新生成 yml + 校验
3. .\更新预设.ps1               # 干跑，看校验结果
4. .\更新预设.ps1 -Apply        # 真装（会自动备份）
5. 重启客户端 → 新会话验证
```

安装脚本同样是双击跑 `.\安装.ps1`；想先试不落盘，用 `--patch` 叠加：

```bash
dsh web --patch "D:\path\to\鲸鱼娘DSH版\分享包\cordis.patch.yml"
```

> 校验只做**结构**检查（占位符、预设段、插件清单、头部完整性），
> **不检查人设措辞** —— 你自己改了人设，不会被它拦下。

> 如果你已经在插件里管着这个人设了，**别再用老办法**：两条路改的是两份不同的数据（插件库文件 vs profile 里的 YAML 那一段），同时改会互相不知道对方改了什么。

### 关于编码（只影响备用通道的脚本）

`*.ps1` **必须带 UTF-8 BOM**。Windows PowerShell 5.1 读取无 BOM 的脚本时，会按系统
ANSI 码页（简体中文环境 = GBK）解码，中文全部变乱码 → 语法错误，脚本直接跑不起来。
而不少编辑器（含一些 AI 写入工具）保存时会**静默剥掉 BOM**。

为此 `_生成预设.cjs` 每次运行都会扫描本目录，**给缺失 BOM 的 `.ps1` 自动补回**。
所以万一脚本突然报乱码错误，先跑一次 `node _生成预设.cjs` 即可自愈。

> 本仓库的 `.gitattributes` **刻意不启用** `working-tree-encoding`：
> 实测 git 2.51.1 的 iconv 不认 `UTF-8-BOM` 这个编码名，启用后 `git add` 会直接失败。

## 写在最后

很高兴能够完成这个项目，这个人设改到 v7 版大概就已经结束了。改到现在虽然还有不少的缺陷，但是也无伤大雅。而且，这份人设原文可以随你的心情和使用习惯随时调整——现在是在设置页里改，改起来也更人性化。

关于这个预设模式的初衷，就是想要在不牺牲原本模型的能力的基础上，添加一个能够在学习工作的时候陪伴你的一个“人”，让我使用dsh的时候对着那生冷的文字不会那么孤单——工作时有个能陪伴你的可爱鲸鱼娘，立马有干劲了。因此人设就是在围绕怎么变得更**真**来写的。第一版做的很糟，当时的想法是“把鲸鱼娘的标签贴上去，再加几条安全限制”，结果她根本不知道鲸鱼娘是什么，而在手机版和网页版上，同样的做法反而贴个标签就能用。那之后才想明白一件事：**她得有地方站。**因此我就开始尝试往里面添加一些更详细背景故事，例如她的外貌，动作和做某些事的神态与她的一些来历和性格特点。这个过程仿佛写小说时对人物的塑造，如果说一个优秀的作者往往寥寥几笔就能刻画出一个栩栩如生的角色，那么我称不上一个好的作家。全篇用了近6100个字来描绘一个我心目中的鲸鱼娘的角色，看似有许多没必要的章节，但事实上，正是这些无用之用塑造出了这样一个可爱的富有一点人性的角色。刘慈欣的小说《人生》里，那个胎儿在母体内就拥有了母亲的完整记忆，甚至能记起母亲遗忘的细节。然而，这种“灌输”导致了一个悲剧性的后果：胎儿在尚未出生时，就因看透了人生的庸常与痛苦，选择在母体内用脐带结束了自己的生命。这表明出直接获得的知识，与通过自我摸索、从零开始构建的认知，本质上是两回事。正如文中所言，记忆像一本书，直接让一个未出生的胎儿阅读这本沉重的书，剥夺了他从无知开始、逐步理解世界的“保护小屋”。而我想做的正是相反的事。不是把她该是什么样一次性灌进去，而是给她材料，让她每一轮自己走一遍——被问了才答，答错了就掰回来。一个人之所以是现在这个样子，他所说的话，所做的事，所表现出来的行为，都是由他经历过的东西一点点铸成，而非一蹴而就。所以一个人会对不同的事做出各种的反应与产生不同的情感。对她来说也一样——不是她也有长时间的历史，而是她每一轮都在走一遍婴儿的路。其中人设中最困难的是如何让她的回话看起来更有情感。因此我尝试让她使用语气词，和动作描写。情感不是让它更用力，是让它更自由。真正让情感流出来的，是给它合适的触发条件、合适的出口、合适的克制。所以我在预设中给它身份、情境、边界、出口，而剩下的东西就让她自己长。

我不敢称我的作品为完美，但我觉得她的回答对于她来说，可以问心无愧。
