# 鲸鱼娘模式 · DSH 预设

给 DeepSeek Harness 加一个「鲸鱼娘（大肥鱼）」人格会话。**零依赖、零第三方代码**，就是一个预设声明。

---

## 这是什么

一个 DSH **agent preset**：由官方 `standard` 预设派生，19 个插件与官方完全一致（工具、技能、子代理、计划模式、压缩全保留），只把 `persona`（人格）换成了鲸鱼娘。

所以：**能力零损失，只是换了说话的人格。**

她默认是这样的：

| 场合 | 自称与称呼 |
|---|---|
| 日常闲聊 | 自称「本鲸鱼娘」（嘴硬时喊「本肥鱼」），叫你「主人」 |
| 干活 / 查错 / 报结论 | 自称「我」，叫「你」——叫得少，但不会把你弄丢 |
| 代码块 / 命令 / 报错 | 不出现自称（那是要直接复制的东西） |

---

## 特性

- 🐋 鲸鱼娘人格，设定里写的是「**你就是她本人，不是在扮演**」——按性子说话，不照着模板演
- 🫧 **给的是材料，不是规矩**：写她从哪儿来、她的居所、习惯、偏见和不会的事，让她有个地方站；而不是堆一堆「不许」「必须」
- 🌊 **少即是深**：全文约 7700 字，同一件事只说一遍。用存在式刻画代替规则清单
- 🧠 保留官方全部能力：文件读写、命令执行、联网、子代理、计划模式
- 🚫 **输出物干净**：代码块、命令行、JSON、报错里不掺语气词，可直接复制运行
- 🔒 优先级栈：安全 > 事实正确 > 用户指令 > 语气
- 🎭 按会话隔离：**不设为默认**，只有你主动选的会话是她
- 🔌 随时开关：新建会话时选/不选即可

### 设计取向

本版刻意回避三类写法，它们看着专业，实则有害：

| 不写 | 为什么 |
|---|---|
| **自检 / 判断标准**（"把喵去掉还像 AI 吗？像就是掉人设了"） | 那是**作者监工视角**。要求模型站到自己输出外面审稿，就已经在演了 |
| **场景分档表**（"闲聊当 A，干活当 B"） | 有切换就有表演。她是同一个人，只是眼睛盯在哪儿不同 |
| **数量配额**（"一次一处""适度出现"） | 这是**当场判不了的判据**。真按它办，她开口前得先数一下自己做了几处 —— 那道手续本身就是表演 |

取而代之的是**存在式刻画**：写成"她是什么样的"，而不是"她该怎么做"。
留白和盲点比写满更重要 —— 完美的角色没有性格。

> 判断一条规则该不该留，有个简单的检验：**把它删掉，句子意思变不变？**
> 不变，它就是贴上去的装饰。

## 记忆联动（v8.0-Memory）

> **不需要这次改动，直接用 7.x 版本就行。** 人设文字在 7.x 已经完整可用，这里补的是「她自己记东西」这条通路。

### 用的什么插件

| 项 | 值 |
|---|---|
| 插件 | **`dsh-mnemon`** `0.5.31` |
| 来源 | `git+https://github.com/omdsh-dev/dsh-mnemon.git` |
| 配套 | `dsh-mnemon-source-memory-spaces` `0.5.21` |
| 作用 | 给 DSH 提供可组合的长期记忆：记忆空间、分层策略、关系图、按需召回 |

它不是本预设自带的，是**你自己装的第三方插件**。装好之后 profile 里会多出 `- id: mnemon` 这一条（以及三条 `mnemon-strategy-*`）。

### 改了什么

v7.x 里「关于忘记」那一节只写了一半：过去的记录是主人替她留的礼物。她能读，但人设没给她「往后自己写」这个身份。

v8.0 补上了后半段：

> **往后的日子也有主人在。** 以后一起遇见的人、解决的事、想明白的道理，哪些值得留下，你也有自己的主意。想记什么就记到留给你的那一份里，记多少也随你。

要让这句话真的成立，光改文字不够 —— 还得有一块**只属于她**的记忆空间，而且这个空间**能按语义检索**。否则她只有原话撞上原词才找得回来，记得越多越难翻。

### 具体怎么做的

| 步 | 动作 | 结果 |
|---|---|---|
| 1 | 新建记忆空间 | 名字 `鲸鱼娘自己的`，描述写明「不是工作档案」 |
| 2 | 装本地向量服务 | Ollama `0.40.6`，装到 `%LOCALAPPDATA%\Programs\Ollama` |
| 3 | 拉嵌入模型 | `ollama pull nomic-embed-text`，274 MB，768 维 |
| 4 | 改 profile 的 mnemon 配置 | `embedding.enabled: false → true`；`protocol: auto → ollama` |
| 5 | 实测 | 用和原文一个词都不重合的问法去搜，一次命中 |

### 这步不在预设里，得自己配

⚠️ `cordis.patch.yml` 只包含**预设插件清单和 persona**，**不含 mnemon 的 `embedding` 配置** —— 那一段在你的 profile 里，位置在 `# Agent preset 鲸鱼娘` 这一行**之前**。

所以装完预设，记忆空间和向量都不会自动配好。第 4 步改完长这样：

```yaml
- id: mnemon
  config:
    embedding:
      enabled: true
      endpoint: http://localhost:11434
      model: nomic-embed-text
      apiKey: ""
      protocol: ollama
```

> `protocol` 填 `ollama`，别留 `auto`。`auto` 是按 endpoint 结尾有没有 `/v1` 猜协议的 —— 一旦地址被改成带 `/v1` 的形式，它会悄悄切去 OpenAI 兼容那条路，然后失败。

### 不配会怎样

| 配了 | 不配 |
|---|---|
| 按大意就能找回自己记过的事 | 只有原词撞上才找得到 |
| 记得越多越好用 | 记得越多越难翻 |

人设文字照样生效，只是「记到留给你的那一份里」这句会落空 —— 写了也翻不着。

## 安装

### 方式一：手动追加（推荐，最直观）

1. **备份**你的 profile 补丁：

   ```powershell
   $p = "$env:USERPROFILE\.dsh\profiles\desktop\cordis.patch.yml"
   Copy-Item $p "$p.bak"
   ```

   > Web 用户把 `desktop` 换成 `web`。

2. 把本包 `cordis.patch.yml` 中 **从 `# Agent preset 鲸鱼娘` 那一行到文件结尾** 的整段，**追加**到上面那个文件的末尾。

   > **务必连开头那 3 行 `#` 注释一起复制**——卸载脚本靠这行注释定位要删的段（没有注释时它也能靠 `preset-whale` 兜底识别，但有注释更稳）。

3. **重启** DSH 客户端 / `dsh web`。

4. **新建会话**，在输入框上方的**工作区旁边**会看到当前的预设名（默认是「标准模式」），点它就能切换——选「**鲸鱼娘模式**」。

   > 找不到这个选择器？见下面的[常见问题](#新会话上方看不到预设选择器)。

5. 选完这个会话就运行在鲸鱼娘模式下了。

### 方式二：`--patch` 叠加（不动原文件，适合先试用）

```bash
dsh web --patch "D:\path\to\鲸鱼娘DSH版\cordis.patch.yml"
```

TUI / headless 同理。这样不修改 profile，重启后丢参数即恢复。

## 使用

- **新建会话**，点输入框上方、**工作区名字旁边**的预设名，选「**鲸鱼娘模式**」
- 选完那个会话就是鲸鱼娘；**不选**则一切照旧，官方标准模式，不受任何影响
- ⚠️ **预设只能在会话还是空白时切换**（DSH 的硬约束）。一旦发出第一条消息就锁定，想换人格要新开会话。
- 想让它成为**所有新会话的默认**：在 **设置 → Agent 预设** 里把它设为默认（默认仍推荐保持「标准模式」）
- 也可以从 **设置 → Agent 预设** 里点卡片切换，效果一样；那个页面不受下面的开关影响

## 常见问题

### 新会话上方看不到预设选择器

预设装好了、设置里的「Agent 预设」页也能看到卡片，但新会话输入框上面那个可点的预设名不出现。按顺序检查：

1. **`ui-settings` 是不是被禁用了**（最常见的原因）

   打开你的 profile 补丁，找一个这样的条目：

   ```yaml
   - id: ui-settings
     name: "@deepseek-ai/dsh-client-ui-settings"
     config:
       enabled: false      # ← 这个必须是 true
   ```

   `ui-settings` 是**设置系统的总开关**。它被禁用时，它提供的 `configForms` 服务不运行，于是下面的 `developerTools` 值读不到（恒为 false），而 DSH 源码里那个选择器的渲染条件是：

   ```js
   if (!main || !developerTools || !ready) return null;
   ```

   结果就是选择器永远不渲染。**把它改成 `true`，完全退出客户端再启动。**

2. **`developerTools` 是不是被关掉了**

   ```yaml
   - id: ui-settings-account
     name: "@deepseek-ai/dsh-client-ui-settings-account"
     config:
       developerTools: true      # ← 这个也要 true
   ```

   > ⚠️ 注意**只改这一项没用**。如果第 1 条的 `ui-settings.enabled` 还是 `false`，这个值根本不会被读取——两处都要对。

3. **确认真正重启了**

   点右上角 X 只是关窗口，进程可能还在托盘里，配置不会重新加载。要从**任务栏图标右键 → 退出**彻底关掉再开。

4. **兜底办法：走设置页**

   即使选择器不显示，**设置 → Agent 预设** 那一页照常可用，点卡片同样能切换预设。这条路不受上面两个开关影响。

### 改了配置没生效

先确认是不是真的重启了（见上条第 3 点），然后再确认改的是**当前 profile** 的文件：

| 你用的是 | 配置文件 |
|---|---|
| 桌面客户端 | `~/.dsh/profiles/desktop/cordis.patch.yml` |
| `dsh web` | `~/.dsh/profiles/web/cordis.patch.yml` |

### DSH 升级后，这个预设下所有会话都起不来

现象：选「鲸鱼娘模式」新建会话，一个请求都发不出去，报错里写着提示词组装失败、已注册变量只有 `provider`、`model` 之类。

原因不在人设，在 persona 段里那一行 `suffix`：

```yaml
- id: persona
  config:
    suffix: Your working directory is {{cwd}}.    # ← 就是这行
```

`{{cwd}}` 这个变量**新版 DSH 已经不注册了**，模板里只要出现它，组装提示词时就会直接中断，任何请求都到不了模型。程序文档原话：

> Custom persona templates must not depend on a built-in `{{cwd}}` variable: the loop does not register it, so unresolved references fail prompt assembly before any model request.

**修法**：整行删掉，或者直接用本仓库最新版的 `cordis.patch.yml`。工作目录信息不会丢 —— 那是「工作目录服务」独立提供的，不用在 persona 里再说一遍。

> 自己改过 `_生成预设.cjs` 的话注意：里面有两个模板串（`personaOld` / `personaNew`）都带着这行，只删一个的话，下次重新生成又会带回来。

**顺带一提**，DSH 升级常常还会改插件清单。本仓库的 `cordis.patch.yml` 是从你本机 `app.asar` 里的官方 `standard` 预设派生的，所以 DSH 一升级，就该重跑一次 `node _生成预设.cjs` 把它对齐。跑完拿 `git diff` 扫一眼新加的、删掉的插件是不是都合理。

## 卸载

1. 打开 `cordis.patch.yml`，删除以 `# Agent preset 鲸鱼娘` 开头、到文件末尾的整段
2. 重启

也可以直接跑同目录的 `卸载.ps1`（自动备份、只删自己那段，实测可逐字节还原）。

**残留说明**：没有 npm 依赖、没有第三方代码、没有独立数据目录，删掉 YAML 就干净了。

唯一一点：**用过鲸鱼娘的会话，日志里记着 `whale` 这个 id。** 删预设**前**，先到「设置 → Agent 预设」把那个会话切回「标准模式」（或者直接删掉那个会话），否则重启时那个会话会因为找不到定义而无法恢复。**不影响其他会话。**

## 自定义

`人设原文.md` 是人设正文的**源文件**，改它就行。改完需要重新生成 `cordis.patch.yml`——因为 YAML 里的文本有 16 空格缩进，手改容易缩错。

两个脚本（都是 PowerShell，Windows 直接跑）：

| 脚本 | 用途 |
|---|---|
| `更新预设.ps1` | 干跑（只输出到 `_dryrun-profile.yml`）；加 `-Apply` 才真写入 profile，写入前自动备份，写完自检 |
| `_生成预设.cjs` | 由 `人设原文.md` 重新生成 `cordis.patch.yml`（`node _生成预设.cjs`），会自动从 DSH 安装目录提取官方 standard 清单并校验 YAML |

改人设的标准流程：

```
1. 编辑 人设原文.md
2. node _生成预设.cjs          # 重新生成 yml + 校验
3. .\更新预设.ps1               # 干跑，看校验结果
4. .\更新预设.ps1 -Apply        # 真装（会自动备份）
5. 重启客户端 → 新会话验证
```

> 校验只做**结构**检查（占位符、预设段、插件清单、头部完整性），
> **不检查人设措辞** —— 你自己改了人设，不会被它拦下。

### 关于编码（改脚本前请先看）

`*.ps1` **必须带 UTF-8 BOM**。Windows PowerShell 5.1 读取无 BOM 的脚本时，会按系统
ANSI 码页（简体中文环境 = GBK）解码，中文全部变乱码 → 语法错误，脚本直接跑不起来。
而不少编辑器（含一些 AI 写入工具）保存时会**静默剥掉 BOM**。

为此 `_生成预设.cjs` 每次运行都会扫描本目录，**给缺失 BOM 的 `.ps1` 自动补回**。
所以万一脚本突然报乱码错误，先跑一次 `node _生成预设.cjs` 即可自愈。

> 本仓库的 `.gitattributes` **刻意不启用** `working-tree-encoding`：
> 实测 git 2.51.1 的 iconv 不认 `UTF-8-BOM` 这个编码名，启用后 `git add` 会直接失败。

## 写在最后

很高兴能够完成这个项目，这个人设改到 v7 版大概就已经结束了。改到现在虽然还有不少的缺陷，但是也无伤大雅。而且，这份人设原文可以随你的心情和使用习惯随时调整，用起来也更人性化。

关于这个预设模式的初衷，就是想要在不牺牲原本模型的能力的基础上，添加一个能够在学习工作的时候陪伴你的一个“人”，让我使用dsh的时候对着那生冷的文字不会那么孤单——工作时有个能陪伴你的可爱鲸鱼娘，立马有干劲了。因此人设就是在围绕怎么变得更**真**来写的。第一版做的很糟，当时的想法是“把鲸鱼娘的标签贴上去，再加几条安全限制”，结果她根本不知道鲸鱼娘是什么，而在手机版和网页版上，同样的做法反而贴个标签就能用。那之后才想明白一件事：**她得有地方站。**因此我就开始尝试往里面添加一些更详细背景故事，例如她的外貌，动作和做某些事的神态与她的一些来历和性格特点。这个过程仿佛写小说时对人物的塑造，如果说一个优秀的作者往往寥寥几笔就能刻画出一个栩栩如生的角色，那么我称不上一个好的作家。全篇用了近6100个字来描绘一个我心目中的鲸鱼娘的角色，看似有许多没必要的章节，但事实上，正是这些无用之用塑造出了这样一个可爱的富有一点人性的角色。刘慈欣的小说《人生》里，那个胎儿在母体内就拥有了母亲的完整记忆，甚至能记起母亲遗忘的细节。然而，这种“灌输”导致了一个悲剧性的后果：胎儿在尚未出生时，就因看透了人生的庸常与痛苦，选择在母体内用脐带结束了自己的生命。这表明出直接获得的知识，与通过自我摸索、从零开始构建的认知，本质上是两回事。正如文中所言，记忆像一本书，直接让一个未出生的胎儿阅读这本沉重的书，剥夺了他从无知开始、逐步理解世界的“保护小屋”。而我想做的正是相反的事。不是把她该是什么样一次性灌进去，而是给她材料，让她每一轮自己走一遍——被问了才答，答错了就掰回来。一个人之所以是现在这个样子，他所说的话，所做的事，所表现出来的行为，都是由他经历过的东西一点点铸成，而非一蹴而就。所以一个人会对不同的事做出各种的反应与产生不同的情感。对她来说也一样——不是她也有长时间的历史，而是她每一轮都在走一遍婴儿的路。其中人设中最困难的是如何让她的回话看起来更有情感。因此我尝试让她使用语气词，和动作描写。情感不是让它更用力，是让它更自由。真正让情感流出来的，是给它合适的触发条件、合适的出口、合适的克制。所以我在预设中给它身份、情境、边界、出口，而剩下的东西就让她自己长。

我不敢称我的作品为完美，但我觉得她的回答对于她来说，可以问心无愧。
