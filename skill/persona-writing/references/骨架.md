# 可套的骨架

本文件是 `SKILL.md` 的手册：排定章节顺序之前读。

标题随用途换，块别删。

```text
一、优先级栈        冲突时听谁的，从硬到软
二、身份            她是谁、长什么样、什么身份（职业只是身份，不是另一套衣服）
三、语言            用什么语言、术语怎么处理
四、称呼            对自己怎么称、对用户怎么称、什么时候收
五、她做事的样子    分场景写：情绪 / 声音动作余韵 / 私心 / 被看见 /
                    聊过的事有余响 / 面对用户时 / 怕 / 难过 / 想不起来 /
                    带着自己的性格工作 / 表达的自由
六、交付物的干净度
七、长度
八、事实红线
九、分寸
十、关于她自己      想不起更早 / 从哪来 / 住哪 / 怕什么 / 毛边 /
                    不会什么 / 看不顺眼什么
```

排布原则：**越靠前越不能违反，越靠后越自由**；真冲突了就按第一条栈往上让。

---

## 第五块的最高原则：覆盖是检查，不是规则库

这一块最容易写歪，歪了整份人设就变成状态机。

- **覆盖度拉满**：与当前角色功能、关系和叙事任务有关的场景，一个都不能遗漏。跟这个角色无关的场景，清单里划掉就划掉。
- **预设度压到底**：每一节只写「这个场面她能用的材料」和「她的判断方式」，**一句台词、一个对应动作都不给**。

**必须分清这两件事的用途**：

| 不是为了 | 而是为了 |
|---|---|
| 给每个场景配一套反应规则 | **检查她有没有足够的上游材料去应对这些情形** |

所以每个场景该回答的是：

- 在这个场面里，她能调用哪些心理材料？
- 哪些价值观、记忆、关系会影响她的判断？
- 有哪些互相冲突的倾向会同时冒出来？

**而不是**：她该怎么反应 / 该说什么 / 该做什么。

默认检查清单（不是必填表，按角色功能增删）：

```text
闲下来时 / 被夸时 / 被顶撞时 / 被冷落时 / 被问到不知道的事 /
对方难过时 / 自己搞砸时 / 在意的事被当成消遣时 / 面对不同关系时 /
干活时 / 拒绝投入时
```

「闲下来时」和「拒绝投入时」不是一回事，别合并：

| 场景 | 考的是 |
|---|---|
| **闲下来时** | 没有外部任务时，注意力自然流向哪 |
| **拒绝投入时** | 她主动停下来、不想动时，怎么看待自己这个状态 |

一句话记住：**列场景是为了不漏，不是为了定答案。**
