# 写人设：造一个能自己长句子的人

## 这份 skill 管什么

**管「怎么造一个人」，不管「造一个什么样的人」。**

下文用「她」指代目标角色，实际对象由使用者替换。正文不出现任何具体角色、外貌、职业设定 —— 那些是产物，不是方法。

**交付物是供扮演的角色卡，不是人物小传。** 评判标准不在「她的人生写得够不够完整」，而在**模型拿到它以后，能不能从她内部出发，持续生成属于她的想法、话、动作和反应**。写得再丰满、但每句话都要作者替她想好，那就是失败的稿子。

三个层次，缺一层就塌：

1. **成为这个人** —— 环境、记忆、性格、习惯、判断逻辑，给一个稳定的出发点。
2. **存在于场景里** —— 动作、神态、语言、空间关系，让她不只是一个说话的声音。
3. **继续成为自己** —— 不预设反应，让她在新情境里靠人格自己判断。

**管不到**：已经在跑的角色出毛病（复读、AI 味重、人设漂移）。那是排查问题：先确认实际输入（逐轮存档里的 system prompt、注入、工具定义）→ 找场景独有变量 → 查靠近生成末端的运行时注入 → 单变量重放。

## 怎么用这一份

本文件是脊：**判据和每步的过关条件都在这里，每次开工都读。**
工序细则在 `references/`（路径相对本 skill 根目录），到下表的触发点就读，**不是想起来才读**。

| 文件 | 收什么 | 什么时候必读 |
|---|---|---|
| `references/造人.md` | 五步造人的细则：环境写什么、记忆三格、性格怎么配代价、习惯、出口的界线 | 进第 3 步之前；**「量现成的」判 D-3、D-5～D-7 时** |
| `references/通道.md` | 动作 / 神态 / 语言各是什么指纹、动作的两个层面、情绪与心理活动、注意力的三处出口 | 动笔写「她做事的样子」之前；**「量现成的」判那三条通道时** |
| `references/写法.md` | 第二人称的两种用法、示例三分法、红线三类的详解、横向检查、白熊效应、**禁令与意向的分界**、加粗预算、感知与知识边界 | 落笔写卡之前；改已有卡时至少读「红线详解」「示例三分法」与「禁令压不住已经在推的东西」；**「量现成的」同** |
| `references/验收.md` | A–H 每一项怎么跑、判据是什么、什么算没跑 | 交付前；「量现成的」模式**一进来就读** |
| `references/骨架.md` | 可套的十块骨架、第五块的最高原则 | 排定章节顺序之前 |

跳过一份的代价不是「少读了几段」，是**漏了却不知道自己漏了** —— 手册里那些条目，理由恰恰是脊上这几行看不出来。

## 前置判断：模式路由

不属于六步之一，接活时先判一次，判完就进第 1 步。

| 模式 | 特征 | 主要动作 |
|---|---|---|
| **从零造人** | 只给了类型、气质、一两句灵感 | 大量补全，但补完要标注 |
| **重构已有** | 给了完整设定，要让角色改版 | 保留固定项，重写可塑项 |
| **只补一块** | 明确说「加个怕的东西」「场景不够」 | 不碰其他块，只补指定处 |
| **量现成的** | 给了一份现成角色卡，要评估它好不好、哪里能改 | **只诊断，不擅自改**：逐条对照验收，标出过 / 不过，等确认再动手 |

判错模式的代价：对「只补一块」跑一遍完整五步，会把原本没毛病的地方一起改坏；对「量现成的」直接开改，会把一份本来能跑的角色卡改出新的毛病 —— 而且改的人还以为自己在修。

**「量现成的」怎么量**：按下面的顺序走，全程不改文件。

1. **先读 `references/验收.md`。** 不读就跑不完 A、B、E、F、G。
2. 过十项自检（D）和在场感（E），先说哪几项不过。
3. 再拿三场景压测（A）和意料之外（B）跑一遍，看哪些「不过」是真会出问题的。
4. **给改稿，不给改动**：逐句写出「原句 → 改后句」，让用户决定要不要落。
5. 只剩确实该改的才动手；改前备份。

**这一模式不按五步造人走，但手册照样要按点翻。** 判 D 的第 3 条（代价关系、边界共用）要翻 `references/造人.md` 第三步；判动作、神态、语言三条要翻 `references/通道.md`。差别只在**不照着造，只照着量**。

判定要诚实：**「勉强过」也要写出来，别四舍五入成「过」** —— 那是模型最该看的地方。

## 执行协议（六步）

### 第 1 步：盘已知 —— 按证据分三档，不按类别分

**不要按「这是经历还是性格」来分约束等级**，同一类信息在不同用户那里的硬度完全不同。按用户怎么说的来：

| 档 | 判据（看原话） | 处理 |
|---|---|---|
| **固定项** | 用户明确说「不能改」「就是这样」，或已是不能改变的既有事实（名字、身份、外貌、称呼规则、系统边界） | 一律不改、不美化、不省略 |
| **可塑项** | 用户说「你看看怎么调整」「可能吧」「我觉得也许」 | 可重写，但保留他的原意方向 |
| **未定项** | 用户没说 | **不能自动当成已确定事实**，也不能凭空补完当真的写 |

关键：**经历、口癖同样可能是固定项。** 用户说「她小时候在海边长大，这个不能改」，那它就是固定项，不是「随便编的经历」。

判据：**用户明确要求保留的东西，丢掉就是事故；用户只是随手抛出的创作灵感，改写成代价关系不算擅自修改。**

### 第 2 步：找缺口 —— 致命与否按任务判断

**致命缺口不是固定清单，而是「缺了它，当前这个角色就无法成立」的那几样。**

默认检查项（按当前模式判断是否必修）：

| 项 | 什么时候是致命缺口 |
|---|---|
| 环境 | 角色要靠所处世界立住（陪伴型、叙事型、有专属空间） |
| 记忆 | 角色要跟人建立连续关系，或情绪有来处 |
| 主矛盾 | 角色存在感来自内在拉扯 |
| 与用户的关系 | 交互型角色 —— 关系本身是设定的一部分 |

反例要能识别出来：

- 纯知识助手 → 不需要个人记忆，硬塞一段反而是噪声。
- 小说里的路人配角 → 不一定要定义「与用户的关系」。
- 工具型角色 → 主矛盾可以整个不存在。

**致命**（缺了立不住）：按上表判断，缺则问。

**问几个**：优先只问**一个**——最影响生成的那个。只有存在多个彼此独立、且都会影响角色成立的致命缺口时，才在同一轮最多问三个。不要为了凑效率一次抛一堆，也不要死守一个而反复打断用户。

用户不在或说了「你先写」，自己补，交付时单列。
**非致命**（习惯细节、标志动作、口癖倾向）：直接补，不问。

**不要为了省事把致命缺口当成非致命缺口补掉。** 环境空着，性格就是悬空的标签。

### 第 3 步：按五步造人

**先读 `references/造人.md`，再动手。** 顺序不能倒：先环境记忆，再性格习惯，最后才是出口。

某一步对这个角色没有必要（工具型角色没有记忆、没有主矛盾），就标「无须强设」直接进下一步。**不得为了走完流程而创造无意义的设定** —— 硬填出来的环境和记忆，比空着更坏，它会让她的行为凭空多出没有来由的因果。

### 第 4 步：处理矛盾 —— 分三种，不是两种

| 类型 | 长什么样 | 怎么处理 |
|---|---|---|
| **条件性冲突** | 不同条件下不同特质占上风 | 写成条件分叉：「平时惜力，但认定的事不糊弄」 |
| **内在拉扯** | 两股力量同时存在、彼此牵制，哪边都不肯让步 | **直接写出来，不解释成谁的代价**：「极想有人陪，又绝不主动开口」 |
| **代价性冲突** | 维持一个特质，必须牺牲另一个的满足 | 写成账：「爱面子，所以在该认错的时候慢半拍」 |

最容易犯的错是把「内在拉扯」压成「条件分叉」—— 一压，张力就没了，只剩一个会切换的开关。

**不要二选一，也不要抹平。**

判据（检验矛盾是否还在，不检验她怎么表现）：

> 在陌生场景里，能不能指出**至少两股方向不同的内在力量**？它们之间是否还在互相牵制？

不看犹豫 —— 有些角色矛盾很深但应对很稳，照样不犹豫。

### 第 5 步：先看增量，再压缩

删之前先问一句更早的问题：**这东西一开始就不该写吗？**

角色卡的篇幅，该花在模型自己猜不到、容易猜错，或者不写就稳不住的地方。每条设定先过一遍：

> 不写这一条，模型能不能自然生成？如果能，它还承担别的作用吗 —— 区分这个人、约束某种行为、维持前后连贯？

| 内容 | 处理 |
|---|---|
| 模型本来就能生成，且不承担区分或约束作用 | 不写，或压缩到一句 |
| 模型本来能生成，但这个人有特殊的程度、条件、边界或表达方式 | 只写那个特殊部分 |
| 模型容易猜错、容易漏、推不出来 | 优先保留 |

举例看区别：

- 「她很温柔」—— 泛化描述，模型不写也会演，删。
- 「她温柔，但不会为了让人舒服就说违心的话」—— 有区分度，留。
- 「她会道谢」—— 增量很低。
- 「她不太习惯把谢说出口，宁可用行动补上」—— 会改变实际生成，留。

**别为了追求独特去造怪癖，也别把基础设定一概删掉。** 判据不是「这句话别致吗」，是「这句话给了模型原本给不出的东西吗」。

上面这张表判断的是**这条设定值不值得写**。还有一种判断是它**相对于模型先验属于哪种增量**，分四种，处理不一样：**推翻**先验的（优先展开）、**加深**先验的（补条件与案例）、**新增**的（优先保留）、**只是证实**先验的（一句带过）。两套分类看的是不同维度，别混成一件事。

**台词样本算「新增」，不属于「只是证实先验」。** 形容词才配得上被压 ——「你很温柔」删掉模型照样演；「清闲得很，说出来怕是不好意思」删掉，这种味道就再也长不出来。

然后才进压缩顺序：

1. 同一件事的重复表述
2. 抽象形容（换成具体名词，或直接删）
3. 不影响场景覆盖的细节
4. 同类场景合并成一节

**不能删**：事实红线、称呼规则、边界句、场景覆盖的分支本身（可压缩措辞，不能整节消失）。

判据：**删完以后，还有哪个场景找不到落点？那个场景就是不能删的那一节。**

### 第 6 步：交付

- 用户要直接用 → 直接给完整角色卡。
- 用户在看设计 → 先给五行摘要（她是谁 / 她在哪 / 她记得什么 / 她的主矛盾 / 这组矛盾怎么牵制她），确认方向再展开。用不上的那几行写「无须强设」，不要空着也不要硬填。

最后一格写「牵制」不写「代价」：内在拉扯未必是谁付出代价，两股力量同时扯着也算。别把拉扯硬翻译成账。

- 补进去的内容单列一段，标明可换。
- 交付前过一遍下面的验收（D 十项与 H 必过，A/B/C/E/F 能跑就跑，G 看角色重要性）。

## 核心：一张层级图

```text
    环境 ──┐
           ├──→ 性格 ──→ 行为 ─┬─→ 动作（最藏不住，带习惯性）
    记忆 ──┘       ↑           ├─→ 神态（心理的外在，具体是表情）
                   │           └─→ 语言（带语气）
                习惯（性格沉淀下来的默认档）

情绪：三条通道共同的燃料
心理活动：燃料本身

人格矛盾：角色需要时写，不需要时不强设   ← 见下
外显反差：三条通道之间对不上的地方        ← 不写，是矛盾的自然结果
```

三条读法：

1. **底厚、骨硬、出口薄。** 环境与记忆写得越具体越好；性格与习惯要配代价和边界；行为只写岔路口。
2. **越藏不住的通道，越交给她当场生成。** 语言会骗人，神态半藏半露，动作最藏不住。所以动作、神态只给材料不给答案。**语言要给两样：嗓音，和结构习惯。**

   **嗓音靠句子，不靠形容词。** 写十遍「软糯温柔」，模型还回来的还是软糯温柔；给三句她真会说的话，它才知道那是什么味道。**结构习惯**是另一件事：先给结论还是先铺陈、什么话她绝不说出口、什么时候换称呼、什么时候收。

   给的是**她自己开口的样子**，不是**某个场景的正确答案**。
3. **往下游写得越细，她能自己决定的事越少。** 每多写一条「A 场景就 B 动作」，就替她决定了一次。

**这张图的每一项都按角色需要取用，不是必填表。** 工具型角色可以整块没有记忆、没有主矛盾；路人配角不必定义与用户的关系。上游空着的时候，别为了把图填满去硬造。

## 区分「人格矛盾」与「外显反差」

这两个词经常被混用，混了就会写错地方：

| | 是什么 | 在哪一层 | 怎么写 |
|---|---|---|---|
| **人格矛盾** | 两股力量同时拉着她，彼此不承认 | 性格层（内部） | **需要时写**；写了就明确，不写成两条互不相干的特质 |
| **外显反差** | 动作、神态、语言之间对不上 | 表达层（外显） | **不写**，是矛盾的自然结果 |

**什么时候「需要」人格矛盾**：角色的存在感、叙事功能或交互魅力本身就靠内在拉扯撑着。

**什么时候不需要**：功能型角色（工具助手、功能性 NPC）。这时**不要为了满足结构而制造冲突**——硬造出来的矛盾会让她莫名其妙地拧巴，比没有更糟；为了填满结构编出来的矛盾，会让她的行为变得没有来由。

**需要的时候为什么一定要写明**：两条力量各自独立写，模型会挑更好演的那条保住，另一边直接丢。这不是推不出来，是它偷懒。

写人格矛盾时，句子里不该出现场景、动作、台词，只该出现两股力量的名字和它们的关系。例：「你很在意别人怎么看你，却不愿意让任何人发现这件事。」

举例：嘴上说不在乎、行为上持续投入 —— 这是**外显反差**；让它出现的原因（自尊与依恋同时存在）才是**人格矛盾**。

写人设时只做内部那件事。硬写外显反差，写出来的是演法，不是人。

通读检查时，找这三种**外显**迹象，作为「矛盾真的落地了」的证据（**前提是角色本来就有内在矛盾**；本来没有的，找不到才对）：

- 性格内部打架（爱面子 ↔ 在意被看见）
- 上下游对不上（不想干 ↔ 手已经在收拾）
- 记忆与当下错位（别的都淡 ↔ 只有一个人清楚）

该有矛盾的找不到，说明三条通道挤成一条了，得回去补内部矛盾。

## 角色卡正文里的否定，先分清它防的是谁

（这份 skill 自己大量用否定讲禁区，那是教学文档，不是角色卡 —— 别把两者混在一起算。）

删之前问三句：**它防的是她的意愿、模型的能力，还是系统的要求？**

| 类型 | 防的是什么 | 性格能否替代 | 处理 |
|---|---|---|---|
| **意愿型** | 她本来就不愿做的事 | 能，且**前提是性格里真的有着落** | 删，或改写成正面倾向 |
| **能力型** | 模型可能做出的错误补全 | **不能** | 保留；但写成「到边界怎么办」 |
| **系统型** | 格式、交付、执行边界 | 与人格无关 | 按适用范围保留 |

三条最容易踩空的：

- **意愿型不能裸删。** 删之前确认这条倾向在性格或边界句里真有着落；没着落就改写成正面塞进性格，不然她真的会敷衍。
- **能力型不能用性格兜。** 诚实的性格不保证不编造。知识、感知、记忆、执行的边界要写清「到了边界怎么办」，而且**要带程度** —— 「不知道就说不知道」写得太平，会滑成「动不动就说不知道」。
- **系统型不要塞进人格。** 格式、代码块这种按适用范围保留，不用性格解释。

还有一条横向的，不在这三类里：

> **不论她的性格支不支持，只要模型有稳定的倾向性偏差，就要判断是否需要单独约束。**

模型普遍爱在结尾加「希望对你有帮助」、爱把话说满、爱替用户决定下一步 —— 这些跟角色是谁无关，**不合她的性格，却照样会发生**，所以不能靠性格兜底。

删与不删，最后都归到一句：**人格决定她愿意怎么做，能力边界决定她知道和做到什么，系统规则决定哪些必须遵守。三者不能互相代替。**

细节（三类各自怎么写、白熊效应什么时候真成立、加粗预算、感知边界）见 `references/写法.md`。

## 验收

验收分两级，别混着说：

- **读一遍打分** —— 你自己读完卡，判断「这个反应像不像她」。这只能告诉你**先改哪儿**，不能告诉你**改对了**。读完觉得过了，不等于真过了。
- **跑一遍看产出** —— 让模型真的带着卡答一遍，和裸答对照。这才说得上「有用」。

| 项 | 查什么 |
|---|---|
| **A. 三场景压测** | 被夸 / 被顶撞 / 答不上来，三条里有没有退回通用话 |
| **B. 意料之外** | 临时想一个没写过的场景：推不出来 → 上游太薄；只推得出一种 → 下游太死 |
| **C. 自由度** | 她有没有「不符合创作者预期、但符合自身人格」的行为空间 |
| **D. 十项清单** | 见下，逐条过 |
| **E. 在场感** | 放进连续几轮对话：她只说话，还是也在场景里动；动作旁白的**位置和形式**是不是永远一个样；连续几条回复的**段落形状**是不是同一个 |
| **F. 反应落点** | 拿对话历史里三句关于对方自己的平陈述，查有没有注意到、有没有落点、是不是她的 |
| **G. 增量盲测** | 带卡 vs 裸答两臂对照，独立评审；不每次跑，留给重要角色 |
| **H. 嗓音存量** | 数卡里「她真的会说的句子」有几条。不看总数够不够，看**有没有至少一句她主动开口的**（讲自己、起头、拒绝、讨要）。只有应答、只有形容词，说明出口那格空着 —— 先补它，别的都等。补的时候一处最多两句 |

A 到 E 是读卡自查，F 是用对话历史检查反应落点，G 是唯一一条要求对照运行的测试，H 是唯一一条**可数**的检查。**跑不了就如实说没跑，不要用读卡打分代替。**

### D. 交付前自检清单（十项）

逐条过，**答不出「是」的，回去改那一条**：

1. 固定项是否全部保留，没有擅自修改事实？
2. 自行补充的内容是否单独标记？
3. 核心特质（或特质组合）是否都有明确的代价关系？同一组相关特质可以共用一条边界，不要求一特质配一条独立边界。
4. **若角色需要**人格矛盾：是否明确写出两股力量及其关系（而不是只写两条独立特质）？**若不需要**：是否避免了为了满足结构而硬造？
5. 动作是否只固定重复性习惯，而非场景反应？
6. 神态是否避免了「情绪 → 表情」的固定映射，只留生理倾向和泄漏位置？
7. 语言是否同时有两样：**能听出这是谁在说话的句子样本**（她主动开口、她讲自己、她拒绝或讨要的样子），和**不把某场景答案定死的结构边界**？只有形容词、没有一句真会说的话，算不过。
8. 重要场景是否有足够的上游材料，但没有固定演法？
9. 能不能应对一个没写过的陌生场景？
10. 是否仍有「不符合创作者预期、但符合人物逻辑」的行为空间？

**A、B、C、E、F、G 怎么跑、判据是什么**：见 `references/验收.md`。
